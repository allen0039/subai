# WebUI 深色 / 浅色主题统一计划

状态：已实施并完成本地验收。本文定义的改造不改变认证、权限、路由、API 或业务数据。

## 1. 现状与目标

截图和现有样式表显示，页面已有 `data-theme="light"`，但仅覆盖了少量背景 token。大量控件仍直接使用深色十六进制颜色：按钮、输入框、状态标签、个人台 Hero、额度弹窗和代码块。因此浅色模式出现白色页面中混入深色输入框/按钮、导航与表格层级不一致的问题；登录页还没有主题切换入口。

本轮目标是建立一套语义化色彩系统，使同一组件在深色、浅色下都使用一致的层级、对比度和状态含义，并保留当前“冷静、工具型、青色强调”的产品气质。

## 2. 视觉决策

### 主题行为

1. 首次访问跟随系统 `prefers-color-scheme`。
2. 用户手动选择后写入 `localStorage`；登录页、管理台和个人台共用同一个选择。
3. 切换控件使用“太阳 / 月亮 + 当前主题”图标按钮，登录页也提供，且有可读的 `aria-label`。
4. 不做自动随时间切换，避免运营页面在工作中突然改变视觉状态。

### 色彩角色

不再让组件直接使用颜色常量；统一以语义 token 表达用途。

| 角色 | 浅色建议 | 深色建议 | 用途 |
|---|---|---|---|
| `canvas` | `#F6F8FB` | `#0B1220` | 页面背景 |
| `surface` | `#FFFFFF` | `#111B2E` | 卡片、侧栏、表格、弹窗 |
| `surface-raised` | `#F0F4F8` | `#17243B` | 悬停、次级容器 |
| `surface-input` | `#FFFFFF` | `#0C1626` | 输入、选择、代码块 |
| `border` | `#D8E0EA` | `#293C58` | 分隔与描边 |
| `text` / `muted` | `#172033` / `#62738C` | `#E7EEF9` / `#9AA9BF` | 主、次文本 |
| `accent` | `#0E7490` | `#22C1DC` | 主操作、激活态、焦点 |
| `on-accent` | `#FFFFFF` | `#06212A` | 强调色上的文字 |
| `success` / `warning` / `danger` | 深色文字 + 浅色底 | 浅色文字 + 低亮度底 | 状态 Badge、告警、反馈 |

强调色保持青色，但主按钮不再沿用与背景不匹配的固定深蓝。危险操作仍只使用红色，警告仅使用琥珀色，避免与主操作竞争。

## 3. 实施阶段

### T1：建立 token 层（已完成）

- 在 `web/src/styles.css` 顶部定义浅色为默认 token，并将 `[data-theme="dark"]` 作为完整覆盖；统一 `canvas`、`surface`、`surface-raised`、`surface-input`、`border`、文本、阴影和四类语义状态。
- 删除后段重复的 `:root` 覆盖，避免 CSS 文件中先定义一套深蓝、后定义另一套灰黑 token 的级联冲突。
- 为阴影、遮罩、焦点环、禁用态、选中态建立 token；不再在组件规则内出现裸色值，允许渐变和图表使用少量经过 token 化的透明色。

### T2：组件逐类迁移（已完成）

- 表单：输入、select、textarea、代码块、筛选栏和 OAuth 回调输入统一改用 `surface-input`；补齐 hover、focus、disabled、invalid 四种状态。
- 操作：主/次/危险按钮改为语义化背景和前景色；浅色模式中的次按钮改为浅色底+边框，不再显示深色矩形。
- 数据：表格表头、行 hover、分页、Badge、flash/error、空态、搜索弹层和 Modal 全部迁移到 token。
- 业务特例：配额弹窗、个人台 Hero、趋势图、导航 active/hover 也同步迁移，确保最显眼的深色遗留不再破坏浅色模式。

### T3：布局和切换体验（已完成）

- 登录页增加与主应用一致的主题切换按钮；认证前后都读取和保存同一主题状态。
- 顶栏把“亮色/暗色”文字按钮升级为图标+提示，窄屏下保持可操作。
- 浅色模式采用略带蓝灰的 canvas 与纯白 surface，侧栏、顶栏和内容区使用不同海拔，而不是大面积纯白。
- 深色模式降低纯黑比例，让卡片、输入和背景有可感知但克制的三层深度。

### T4：可访问性与质量门槛（已完成）

- 所有正文和交互文字达到 WCAG AA：普通文字至少 4.5:1，大号文字至少 3:1；焦点环在两种主题下都清晰可见。
- 不以颜色作为唯一状态信号：Badge 保留文字，错误/成功消息保留图标或明确文案。
- 保持 `prefers-reduced-motion`；主题切换只使用 150–200ms 的背景/边框过渡，不对布局或数据做动画。
- 用 CSS 静态检查禁止新的非 token 化颜色进入通用组件区；额度图与状态色列为明确例外。

### T5：验收与发布（本地验收已完成，发布待单独授权）

- 在 1440px 和 390px 宽度分别验收登录页、用户管理表格、仪表盘、额度弹窗、个人台、错误/空态、搜索弹层。
- 检查“首次跟随系统 → 手动切换 → 刷新后保持 → 退出登录后保持”的完整链路。
- 运行 `npm run build`、现有前端/API 集成测试和一次浏览器视觉回归；确认无业务接口、Hash 路由和会话行为变化。
- 通过后按 `docs/RELEASE.md` 发布一个补丁版本（建议 `0.2.1`）。

## 4. 验收标准

- 浅色截图中不存在黑色输入框、深蓝次按钮或与页面不协调的深色卡片。
- 深色截图中卡片、输入框、侧栏和背景能明确区分三层，但不使用刺眼纯黑/纯白大面积对撞。
- 相同控件在两主题下结构、尺寸、状态文案完全一致，仅颜色与阴影变化。
- 登录页和登录后的控制台均可切换主题，刷新后保持选择。
- 所有常用按钮、输入、表格状态、模态框和错误状态达到对比度与键盘焦点要求。

## 5. 不在本轮范围

- 不更换 React、路由或引入 Tailwind/UI 框架。
- 不重做信息架构、不增加后端接口、不改变权限与业务流程。
- 不为“好看”引入大面积渐变、玻璃拟态或营销式插画；SubAI 保持运营控制台的克制感。

- 构建与代码检查：`npm run build`、`git diff --check` 通过。
- 回归：`go test ./...` 与 `make test-integration`（Docker PostgreSQL）通过。
