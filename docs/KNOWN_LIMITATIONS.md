# 已知限制

第一版交付时的真实边界。逐条与 IMPLEMENTATION_PLAN.md 对应，不做未经验证的能力声明。

## 协议与上游

1. 上游 Codex 协议（端点、SSE 事件 schema、usage 字段、previous_response_id 行为）未经真实账号验证（P0-01 blocked，见 docs/COMPATIBILITY.md）。所有上游交互测试基于合成上游。
2. WebSocket 不支持（D-010）。/v1/chat/completions 不支持，等待 Hermes 实测需求。
3. previous_response_id、压缩历史、加密推理内容等"网关不可见上下文"的调用形式在严格模式下返回 422 audit_unsupported（§6.1），兼容矩阵单列 pending。
4. 官方桌面端直接登录同一账号的消耗不经过网关，无法记账或审核（§2.2）。

## 预算

5. 输出上界依赖注入 max_output_tokens（D-001）；上游是否在所有工具调用场景尊重该参数待 P0-02 验证。
6. 输入 token 为保守估算（D-002），预留偏大；结算按上游真实 usage。
7. 内部美元是按内部价格表的折算值，不代表官方订阅余额或官方 API 余额（§2.1）。
8. 默认种子价格为 synthetic 占位（D-008），不得用于生产调用；production_ready 要求已验证的官方价格版本。

## 审核

9. Moderation 是内容分类器，不是违法行为/提示词注入/数据外传的通用判定器（§2.4）。本地规则 flag 只记录风险，不改变官方判定。
10. 全文分段审核存在跨段意图遗漏风险（§2.5）；不承诺零误判/零漏判。
11. 审核缓存仅对完全相同的规范化输入生效；不采用"单段通过放行新组合"的优化（§6.2）。
12. 图片审核依赖 omni-moderation 的实际支持范围，未实测；不支持时返回 unsupported 而非放行。

## 运维

13. 单活实例：第二实例因数据库单活锁无法启动（D-007）；多实例协调不在第一版。
14. 迁移无自动回滚（D-005），依赖备份恢复流程。
15. 队列期限参数（30s 等待/60s 总期限）为设计初始值，需真实长上下文负载校准（§6.3）。
16. 日志默认保留 14 天；账本不跟随审计日志删除。
