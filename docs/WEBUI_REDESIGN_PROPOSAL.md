# SubAI WebUI 重设计方案（v1 提案）

> 目标：告别"15 个平铺菜单 + 一摞白表格"的观感，借 sub2api 与 CPA 之长，做一套属于 SubAI 自己的、独特且美观的运营台 + 个人台界面。
> 本文档是设计方案，不含代码改动；确认方向后再排期实施。

---

## 一、现状诊断

当前 UI（`web/src/styles.css` + `App.tsx`，纯手写 CSS，零 UI 依赖）的主要问题：

| # | 问题 | 具体表现 |
|---|------|----------|
| 1 | **导航平铺过载** | 管理端 15 个一级菜单从上到下一字排开，无分组、无层级，找"预算周期"要扫完整个侧栏 |
| 2 | **没有真正的仪表盘** | "状态"页只是文字列表；sub2api/CPA 打开即见的统计卡、图表、池子健康度，这里完全没有 |
| 3 | **表格即页面** | 所有业务页都是同一张"表格 + 新建弹窗"，缺筛选栏、缺详情承载（详情全靠弹窗，弹窗里再塞弹窗） |
| 4 | **视觉平淡** | 深蓝底 + 蓝色 accent 一用到底，无层次（elevation）、无品牌记忆点、无动效；只有暗色主题 |
| 5 | **最有价值的"配额快照"被埋没** | 5 小时/每周双窗口配额是 SubAI 最独特的数据，却缩在账号表格的一个百分比里 |
| 6 | **无反馈节奏** | 无骨架屏、无空状态插画、无加载动效，点击后是"白屏→表格" |

优势（ redesign 必须保留的资产）：哈希路由 + 声明式 `ResourcePage` 骨架（改造成本极低）、quota-modal 的窗口进度条模式（全 UI 最精致的部分）、纯中文本地化、代码量小（~1.7k 行）。

## 二、参考项目拆解：借什么，避什么

### sub2api（Vue3 + Tailwind，经典运营后台）

**布局**：左侧栏管理后台 + 独立用户控制台；仪表盘以"统计卡 + 实时监控图表（QPS WebSocket）+ 数据表格"为核心；系统设置按层级归组（系统设置 → 网关服务 → 策略）；带首次部署向导。

- ✅ 借鉴：**统计卡 + 实时图表的仪表盘范式**；设置类功能的**层级归组**；用户端与运营端分离的双台结构（SubAI 已有雏形，可以做得更清晰）。
- ⚠️ 规避：它偏"商用多租户 SaaS"，充值/支付/营销味重；SubAI 是圈子内网关，应该更冷静、更工具化，不堆营销模块。

### CPA（Cli-Proxy-API-Management-Center，React 单文件工具面板）

**布局**：按功能域切页（Dashboard / Config / Providers / Auth Files / OAuth / Quota / Logs / System）；每页顶部有连接状态 + 快速计数摘要；配置类操作用可视化编辑器 + 源码编辑双模式；日志页带增量轮询 tail。

- ✅ 借鉴：**"一页一域、页首摘要条"的工具型组织**；Dashboard 的**快速计数 + 状态快照**；日志/事件的实时 tail 思路。
- ⚠️ 规避：它是纯单机工具，没有多角色概念；配置页直接暴露 YAML 的做法不适合 SubAI 的订阅/预算模型。

### 结论：SubAI 的定位公式

> **sub2api 的"运营后台骨架"（统计卡 + 图表 + 分组导航） × CPA 的"工具面板密度"（页首摘要条 + 一页一域） − SaaS 营销味 + SubAI 独有的"配额窗口"视觉母题。**

## 三、设计定位与独特记忆点

**概念：「控制塔（Control Tower）」** —— 你不是在"管理一堆表"，而是在塔台上俯瞰整条链路：用户请求 → 策略 → 账号池 → 出口。整个 UI 围绕三个独有记忆点展开：

1. **双环配额仪表（Quota Ring）** —— 5 小时窗口 + 每周窗口用嵌套双环呈现，作为全 UI 的视觉签名：仪表盘的池子矩阵、账号表格行内、会员概览、密钥详情，全部复用同一组件。别的网关面板没有这个东西。
2. **链路状态条（Pipeline Strip）** —— 把 README 里的处理链（鉴权/限流/预算 → 规则 → 审核 → 队列 → 选号 → 出口）做成状态页顶部的一条可点击管线，每段显示当前健康度和今日调用量，一眼看出"哪里堵了"。
3. **"订阅 → 密钥 → 账号池"链路卡** —— 会员端首页用三段连接卡呈现这条主链（保留现有 UI 的签名概念，升级为带状态灯和流量的流程图样式）。

**设计关键词**：冷静（克制用色）、精确（等宽数字、tabular-nums）、有层次（三段式海拔）。

## 四、信息架构与导航重组

### 4.1 管理端：15 项 → 5 组

侧栏改为**分组标题 + 可折叠分组**，常驻 "概览" 在最顶：

```
◈ 概览
    仪表盘            （原"状态"升级，默认落地页）
    用量账本
── 用户与订阅 ──
    用户管理          套餐管理
    订阅分配
── 资源池 ──
    上游账号          账号池
    代理出口
── 策略 ──
    出口策略          预算策略
    预算周期          价格版本
── 审计 ──
    审核规则          审核事件
    管理事件
```

### 4.2 会员端：4 项保持，但首页重做

`我的概览 / 我的密钥 / 我的订阅 / 账户安全` 结构不变，概览页按第六节重做。

### 4.3 骨架布局：侧栏 + 顶栏双件套

```
┌──────────┬──────────────────────────────────────────────────┐
│ SIDEBAR  │  TOPBAR (56px, sticky)                           │
│ 240px    │  面包屑        [🔍 全局搜索 ⌘K]   ⟳   🌓   👤▾  │
│ 可折叠    ├──────────────────────────────────────────────────┤
│ 至 64px  │                                                  │
│ 图标轨    │   CONTENT（24px 边距，页面标题区 + 页首摘要条）      │
│          │                                                  │
│ 品牌区   │                                                  │
│ 分组导航  │                                                  │
│ 版本号    │                                                  │
│ 身份/退出 │                                                  │
└──────────┴──────────────────────────────────────────────────┘
```

- **顶栏**：面包屑（分组 / 页面）、⌘K 全局搜索（搜用户/密钥/账号，直接跳转——管理端最高频动作）、手动刷新、主题切换、头像菜单。
- **侧栏折叠**：默认展开，折叠后只剩图标（hover 出 tooltip），小屏自动进抽屉。
- **页首摘要条**（学 CPA）：每个资源页顶部一行内联摘要，如账号池页：`上游账号 12 · 可用 9 · 降级 2 · 不可用 1 · 五小时窗口整体 43%`。

## 五、视觉语言（Design Tokens）

### 5.1 色彩：从"深蓝海军"换成"午夜石墨 + 极光青"

摆脱现有满屏蓝调，底色转中性冷灰，品牌色换成青色系，与数据语义色彻底分开：

| Token | 暗色（默认） | 亮色 | 用途 |
|---|---|---|---|
| `--bg` | `#0b0d12` | `#f5f6f8` | 页面底 |
| `--surface` | `#13161d` | `#ffffff` | 卡片/面板 |
| `--surface-raised` | `#1a1f29` | `#ffffff` | 弹层/悬浮卡（带阴影） |
| `--border` | `rgba(255,255,255,.07)` | `rgba(15,23,42,.10)` | 描边 |
| `--text` | `#e8ebf1` | `#0f172a` | 主文字 |
| `--muted` | `#8a93a5` | `#64748b` | 次文字 |
| `--accent` | `#22d3ee` | `#0891b2` | 主操作/链接/选中态 |
| `--accent-grad` | `#22d3ee → #818cf8` | 同 | 品牌 logo、主按钮 hover、概览英雄区，**仅限点缀** |
| `--ok` | `#34d399` | `#059669` | 正常/可用 |
| `--warn` | `#fbbf24` | `#d97706` | 高负载/待审 |
| `--danger` | `#f87171` | `#dc2626` | 不可用/超额 |
| `--info` | `#818cf8` | `#6366f1` | 信息/管理员标识 |

原则：**青色只给"可交互"**，绿色/黄/红只给"数据状态"，界面九成面积是中性灰，状态色才醒目。

### 5.2 排版与数字

- 字体沿用 Inter + Noto Sans SC + PingFang SC；**所有数值（金额、百分比、Token 数、时间戳）一律 JetBrains Mono + `font-variant-numeric: tabular-nums`**，表格内右对齐。
- 字阶：12（辅助）/ 13（表格正文）/ 14（正文）/ 16（卡片标题）/ 20（页面标题）/ 28（统计卡大数字，配 mono）。

### 5.3 形状、海拔与密度

- 圆角：卡片 12px，按钮/输入 8px，徽章全圆。
- 三档海拔：`flat`（页面底上的卡片，仅描边）→ `raised`（hover/粘性元素，描边+轻阴影）→ `overlay`（弹层/抽屉，深阴影）。
- 表格行高 40px（运营密度），卡片内边距 16/20px。
- 动效：只做三处——页面切换 fade+8px 上移（120ms）、抽屉滑入（200ms）、Quota Ring 数字滚动；不搞大面积动画（学 CPA 用 Motion 的克制版）。

### 5.4 明暗双主题

暗色为默认（运维场景），亮色为完整一等公民（同一套 token 换值即可，`data-theme` 切换 + localStorage 记忆）。

## 六、核心页面设计

### 6.1 仪表盘（管理端落地页）

```
┌ 页首摘要条：网关运行 27 天 · 今日请求 18,432 · 成功率 99.2% · 活跃密钥 23 ┐
│                                                                        │
│  [今日请求 ▁▂▅▇▆▃▂▁ 24h 面积图]   [今日成本 $12.40]  [失败率 0.8%]      │
│  ┌──────────────────────────┐  ┌──────────────────────┐                │
│  │ 账号池健康矩阵            │  │ 最近事件流            │                │
│  │ ┌──┐┌──┐┌──┐┌──┐┌──┐    │  │ 14:32 某号 5h 窗口→黄 │                │
│  │ │◉◉││◉◉││◉○││◉◉││○○│    │  │ 14:28 审核拦截 1 条   │                │
│  │ └──┘└──┘└──┘└──┘└──┘    │  │ 14:01 新密钥创建      │                │
│  │  每格=1 上游账号           │  │ （可 tail，学 CPA 日志）│                │
│  │  内环=5h 外环=weekly      │  └──────────────────────┘                │
│  └──────────────────────────┘                                          │
└────────────────────────────────────────────────────────────────────────┘
```

- 顶部 4 张统计卡（大号 mono 数字 + 迷你趋势线）；24h 请求面积图用手写 SVG 实现（不引图表库，见 §8）。
- **池子健康矩阵**是本页主角：每个上游账号一格双环仪表，按"健康/降级/不可用"排序，点击直达账号详情。
- 最近事件流聚合审核事件 + 管理事件 + 配额变化，实时轮询。

### 6.2 上游账号页（最重的资源页）

```
页首摘要条：12 账号 · 9 可用 · 池整体 5h 43% / weekly 61%
[搜索邮箱] [状态▾] [套餐类型▾] [池▾]        [+ 接入账号]
┌──────────┬──────┬────────────┬──────────┬────────┬──────┐
│ 账号      │ 状态  │ 配额双环    │ 所在池    │ 出口   │ 操作  │
│ a@x.com  │ ●可用 │ ◉◉ 5h 82%  │ pool-1   │ JP-01  │ ⋯    │
│          │      │    周 61%   │          │        │      │
└──────────┴──────┴────────────┴──────────┴────────┴──────┘
```

- **Quota Ring 从弹窗升格为表格列**：小号双环（36px）+ 数字，hover 展开详情。
- 行点击 → 右侧**抽屉**（替代原 quota-modal 承载账号详情：完整双环大图、重置倒计时、同步时间、操作按钮），弹窗只留给"接入账号"表单。
- 原有的"刷新配额"按钮保留在抽屉头部，配 loading 骨架。

### 6.3 通用资源页模板（ResourcePage v2）

所有 15 个业务页共用同一模板，结构固定为：

```
页首摘要条 → 工具栏（搜索/筛选/新建） → 表格 → 底部分页
```

- 筛选从"无"到"每页至少一个主筛选"（声明式配置在现有 columns/fields 里加 `filters` 即可，改造成本低）。
- 详情统一走抽屉，新建/编辑走弹窗——**弹窗管"写"，抽屉管"读"**。
- 空状态带引导插画/文案（"还没有套餐，点击右上角创建第一个"）。

│  ┌─────────┐   ┌─────────┐   ┌─────────┐     │

### 6.5 登录页

居中卡片 + 极光渐变品牌光晕背景（纯 CSS，克制的一处渐变使用），保留角色切换（运营台/个人台）。

## 八、技术落地方案

现状：React 18 + Vite + 手写 CSS（189 行）+ 哈希路由 + 声明式 ResourcePage，零运行时依赖。两条路线：

**方案 A（推荐）：Tailwind CSS v4 + 手写组件层**
- 引入 Tailwind v4（仅构建期依赖，v4 零配置、CSS-first 的 `@theme` 正好承载第五节的 token），组件全部自写（§7 清单，不引组件库）。
- 路由不动（哈希路由够用）、ResourcePage 骨架不动（升级内核）、`styles.css` 退役为 token 文件。
- 优点：改造成本低、和 sub2api 同栈便于长期借鉴、暗亮主题只需切 CSS 变量。图表坚持手写 SVG（需求只有面积图/迷你线/双环，不值得引 Chart.js/uPlot，保持零运行时依赖的传统）。

**方案 B：纯手写 CSS 重构（不加任何依赖）**
- 沿用 CSS 变量体系直接重写 styles.css（预计 ~600 行）。完全零依赖，但筛选栏/抽屉/响应式的样式成本会吃掉收益。

工作量粗估（方案 A）：

| 阶段 | 内容 | 预估 |
|---|---|---|
| M1 | Token + AppShell（侧栏/顶栏/主题切换）+ 基础组件 | 1 天 |
| M2 | 导航分组重组 + 面包屑 + ⌘K 搜索 | 0.5 天 |
| M3 | 仪表盘（统计卡/池子矩阵/事件流/SVG 图表） | 1.5 天 |
| M4 | ResourcePage v2（筛选/抽屉/表格升级）+ 账号页与 QuotaRing | 1.5 天 |
| M5 | 会员个人台重做 + 登录页 | 1 天 |
| M6 | 亮色主题联调 + 移动端 + 空状态/骨架屏打磨 | 1 天 |
