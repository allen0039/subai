# Sub2API「运行工作台」UI 重构实施方案

日期：2026-09-15
状态：可进入实施；本轮完成计划，尚未实施产品改造。
设计依据：已选定 A+C 融合概念图，深色运行总览、窄导航、流量主图、额度横条、健康矩阵、右侧详情。

## 1. 目标与交付边界

将当前传统侧栏与卡片式后台重构为统一工作台。核心路径为：发现异常 → 选择平台/分组/模型 → 查看真实指标与日志 → 进入对应资源操作。管理员先行，用户端随后使用同一套组件和主题，但只展示本人数据与可用功能。

最终交付包括：设计 token、导航与布局系统、管理员运行总览、联动详情面板、核心管理页迁移、用户端迁移、其余页面一致性检查、可回退发布方式及验收记录。保留现有业务能力、权限、计费口径、国际化、功能开关、自定义菜单与原 GPT 上游 OAuth 流程。

首版采用受控模块布局：显示/隐藏、排序、标准/宽两档，支持恢复默认。自由拖拽画布、跨设备布局同步、全站实体搜索、新预测算法和新告警引擎不进入首版。搜索先提供有权限的页面与操作入口；页面内实体搜索继续复用现有查询。

## 3. 页面结构与视觉规格

### 3.1 布局

- 顶栏高 56px：站点品牌、管理/个人入口、命令搜索、公告通知、个人菜单。
- 主导航宽 76px：图标配文字；列表页按需出现 168–200px 二级导航。总览页直接展示主画布。
- 内容内边距 20–24px，模块间距 16px；详情面板 320–360px。
- ≥1440px：主画布与右侧详情并排；1100–1439px：详情改覆盖抽屉；768–1099px：模块单列或双列，二级导航改顶部选择器；<768px：折叠菜单，详情全屏，表格局部横向滚动。
- 页头后为紧凑指标条；流量主图占主要可视区域；下方额度列表与健康矩阵；最近请求使用紧凑表格。小屏允许自然纵向滚动，不强行缩小文字。
- 大表格页优先表格空间，详情按需展开；表单按内容分区，少量字段仍可弹窗，复杂编辑保留完整页面/现有流程。

### 3.2 主题与组件

| 语义 | 深色基准 |
| --- | --- |
| 页面背景 | `#121923` |
| 模块表面 | `#1A2431` |
| 分隔线 | `#2C3949` |
| 主要文字 | `#EAF0F6` |
| 次要文字 | `#9EAFBF` |
| 正常/主曲线 | `#4DCBB9` |
| 注意/异常提示 | `#F5B75B` |
| 选中/主要操作 | `#709CF8` |

以 CSS 变量表达 background/surface/text/border/accent/success/warning/danger，不在业务模板散写色值。另定义明确失败状态色，并对实际前景/背景组合验证对比度；状态同时有文字/图标。保留浅色模式与已有主题偏好，首版需同时验收两种模式。

中文沿用系统无衬线字体，数字使用等宽数字特性，技术标识使用等宽字体；标题 24–28px，正文 14px，辅助 12px。圆角 6–8px、少量阴影；交互过渡 120–180ms，支持减少动态效果。统一按钮、输入框、下拉、标签、表格、弹窗、抽屉、空态、骨架和错误提示。

## 4. 导航与全站迁移

主导航按任务分组，所有现有可见入口须有归属；不可因概念图只有六个图标而删除功能。

| 主入口 | 二级内容 |
| --- | --- |
| 总览 | 运行总览、已有高级运维分析 |
| 渠道与资源 | 渠道配置/定价、上游账户、分组、代理、启用的监控配置 |
| 用户与业务 | 用户、订阅、订单/套餐、启用的推广功能 |
| 用量 | 用量记录、已有统计明细 |
| 审计 | 操作日志、已启用的风控与提示词审计 |
| 设置 | 系统设置、公告、插件、自定义页面入口 |

管理员通过顶栏进入个人空间。用户端导航为概览、密钥、用量、可用渠道/监控、订阅/订单、个人设置，并遵循实际功能开关；保留批量图片入口和启用的自定义页面。已移除或禁用的功能不因概念图出现而恢复。

保持现有 URL 和路由守卫。导航配置是唯一入口定义来源，桌面、移动、命令搜索共用过滤结果。P0 输出逐路由迁移清单，包含隐藏条件、角色、当前路径、目标分组及验收状态。

## 5. 数据契约与概念图修正

### 5.1 指标来源

| UI 模块 | 首选来源/口径 | 限制与处理 |
| --- | --- | --- |
| 今日请求与金额 | 管理仪表盘 stats/snapshot | 请求、用户实际扣费、上游账户成本分别标注；不统称“消耗” |
| 成功率、错误率、P95 | V2 snapshot 的 metrics/health | 明示所选范围；使用服务端口径与忽略类别，不混用 Ops SLA |
| P95 | `duration.p95_ms` 或 `ttft.p95_ms` | 默认标“请求耗时 P95”；TTFT 单独标“首字延迟 P95”；不平均各组 P95 |
| 流量主图 | V2 snapshot.trend | 首版范围为接口已有 `90m/24h/7d/30d`，不假设图中的 1h/6h 已支持 |
| 健康矩阵 | V2 matrix | 平台/分组/模型维度，不伪装成单账户渠道 |
| 额度横条 | 已有关联账户/监控的额度快照 | 按实体、单位与窗口分别显示；来源不足时显示未配置或未知 |
| 最近请求 | Ops 请求详情或已有用量查询 | 检查实际字段及过滤支持；费用无来源显示“—”，失败请求不默认费用为零 |
| 事件 | 已有 Ops 告警/错误记录 | 无实体和时间对应证据时不绘制“异常事件”标记 |

今日指标固定显示统计日期/时区；图表与成功率/P95随所选时间范围变化，用分组标题区分，不能让同一“今日”标题包含不同范围数据。不同来源不得假定同一采样截止时间，显示更新时间和覆盖提示。

额度特别规则：5h/7d/daily 等窗口不相加；USD、其他货币、tokens、requests 不合并。只有全部成员单位、窗口、统计范围一致且采集完整时才允许汇总，否则展示分账户额度。空值不当作 0 或无限，禁用额度与未知额度分开表示，超额保留原值并标注。

### 5.2 详情面板实体绑定

首版右侧面板名为“运行详情”。使用结构化选择状态：

```ts
type InspectorSelection =
  | { kind: 'aggregate'; platform: string; groupId?: number; model?: string }
  | { kind: 'monitor'; monitorId: number; accountId?: number }
  | { kind: 'account'; accountId: number }
```

选择健康矩阵行打开 aggregate 详情，可展示同维度趋势、错误分布和支持的日志筛选。选择具体监控任务或账户才展示其配置、额度与已有测试操作。禁止按“Claude·02”等显示名称推断关联。聚合详情无法准确定位资源时，仅提供“查看关联资源”，不出现直接编辑/测试单账户按钮。

若必须实现概念图中的“每行单渠道 + 同渠道 P95 + 日志 + 额度”，先核实真实请求记录是否有稳定渠道/账户关联及聚合索引，再单独补充服务端契约、查询成本评估与迁移测试。这是增强项，不能用前端猜测替代。

### 5.3 请求与状态

- 建议新增 `features/operations-workbench/` 容纳工作台组件、数据适配器和 composable，沿用现有 API 模块。
- 页面层统一驱动刷新，初始按监控配置的 60/300 秒周期执行；隐藏页面暂停，返回页面按数据时效刷新；禁止组件各自重复轮询。
- snapshot 与 matrix 并行加载，详情按需加载；筛选切换 AbortController 取消旧请求，序号校验防止旧结果覆盖。
- URL 保存支持的筛选与详情选择，校验参数后恢复；不把密钥或请求正文放入 URL/localStorage。
- 分模块处理 loading/empty/error/stale/disabled/unauthorized。样本不足、历史回填、聚合滞后沿用 coverage/health 语义，不呈现为“全部正常”。
- 监控关闭时展示禁用说明与可访问的设置入口，其余仪表盘仍可使用。数据不可用时不自动恢复旧探测系统。

实施提交建议按阶段拆分，页面迁移再按业务域拆分；每次提交保持可构建。保留 Vue/Pinia/Chart.js 技术栈，首版无需引入另一套 UI 框架。

## 7. 验收清单

### 7.1 业务与交互

- [ ] 管理员与普通用户菜单正确；直接访问无权限路由仍被拦截；开关关闭时导航、命令搜索与相关模块同步隐藏。
- [ ] 矩阵选中、详情加载、日志跳转、返回后的筛选和滚动恢复成立；详情 Escape 关闭并恢复焦点。
- [ ] 切换平台/模型/范围后没有上一选择的数据闪回；刷新不会重置打开的详情。
- [ ] 额度正确展示未知、未配置、禁用、超额、过期快照和不同窗口。
- [ ] 单次主动测试仅在用户点击后执行；按现有接口展示运行状态，阻止重复提交。
- [ ] 上游账户 OAuth、Key 管理、订阅/支付/订单和开启的扩展流程无回归。
- [ ] 布局偏好按用户和角色隔离、有版本号；损坏/过期配置回退默认；退出登录清理内存状态。

### 7.2 数据与性能

- [ ] 相同筛选/时间范围下与接口响应逐项核对计数、金额、单位、P95及采样时间。
- [ ] 覆盖零请求、仅失败、样本不足、回填、超时、403、功能关闭；部分失败不使整页空白。
- [ ] 无按所有渠道逐个请求的首屏 N+1 模式；主图/矩阵复用聚合接口，细节懒加载。
- [ ] 建议测试夹具：100 行×96 桶矩阵、1000 条逻辑列表数据（分页/虚拟化展示）；矩阵超过阈值按分组分页或虚拟化。
- [ ] 在记录的设备/浏览器条件下，已加载页面的点击反馈目标 ≤100ms；新页面路由代码按需加载；相同接口条件下首屏耗时不比基线明显退化（超过 20% 必须定位）。
- [ ] 隐藏页不持续发监控请求，卸载无遗留计时器或网络订阅。

### 7.3 视觉与工程

- [ ] 1920、1440、1280、768、390px 视口核对；页面无意外横向滚动，图例/数字不遮挡，长名称可读。
- [ ] 深浅主题均检查总览、列表、编辑表单、抽屉、空态、错误态；文本对比度满足常规 AA 要求。
- [ ] 键盘可打开导航、选择矩阵、关闭面板；覆盖式抽屉管理焦点，固定详情不错误锁定焦点。
- [ ] 复用既有测试，补充数据适配/选择状态/权限过滤/取消过期请求等有价值的测试，不按每个静态样式写测试。
- [ ] 在 frontend 运行 `pnpm run lint:check`、`pnpm run typecheck`、`pnpm run test:run`、`pnpm run build`；记录基线既有失败和新增失败。build 包含 i18n 完整性检查。
- [ ] 若新增后端接口，对改动 Go 包执行针对性测试，并核对权限、空值、统计维度和分页；纯前端阶段不要求重写后端。
- [ ] 使用浏览器验证真实可用环境；测试数据或服务不可用则明确标记尚未验收，不能以静态概念图替代。

## 8. 发布与回退

新增独立界面模式开关（建议 `legacy/workbench`，实现前核对现有设置机制），默认为旧版，管理员试用后逐步启用。共用导航配置、API和业务组件，避免复制两套业务实现。仅迁移已验收页面，其余页面可继续使用旧壳层。

首版不改计费/调度数据结构。回退通过界面开关或前一版本构建完成，不修改业务数据；布局偏好带版本并可忽略。每批迁移前检查工作区变化，保留已有 `bin/` 等无关内容。P6 记录旧版/新版切换、角色与功能关闭场景的演练结果。

本计划不等同于已授权部署；实施完成后交付可运行版本、截图、验证结果与发布说明。上线步骤在具体发布任务中执行。稳定后另行清理旧壳层，避免在试用阶段失去回退入口。

## 9. 可直接执行的首批任务

1. 记录分支/版本、未提交变更，列出全部路由与可见性；跑现有 frontend 验证形成基线。
2. 获取当前总览、Ops、账户、用户端的深浅主题截图与脱敏接口样本。
3. 固定 V2 指标口径、采样范围、额度实体与单位规则，建立工作台数据适配类型。
4. 创建作用域 token 与 WorkbenchLayout；抽取共享导航，接入新旧布局开关。
5. 在现有管理员总览路由下以新模式接入真实 snapshot/matrix；先交付总览、矩阵和 aggregate 详情。
6. 验收该纵向流程后扩展具体账户/监控详情、核心管理页面和用户端。

第一批交付的衡量标准是：管理员能够在新壳层内使用真实运行总览，选择一行监控维度查看匹配详情并进入对应日志，同时可切回原版。随后按阶段完成整站迁移。
