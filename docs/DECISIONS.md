# 决策记录

按计划第 14 节要求记录规格冲突、取舍与依据。每条注明日期与影响。

## D-001 严格预算的输出上界：注入 max_output_tokens

- 日期：2026-09-12
- 规格：§2.6 严格美元上限依赖可验证的请求费用上界；§18.3 预留"可证明的最高费用"。
- 决策：网关在 dispatch 前对 `/v1/responses` 请求注入 `max_output_tokens = min(客户端值, 配置 gateway.max_output_bound)`（默认 4096，管理员可调）。若客户端未指定，注入配置默认值。预留金额 = 输入估算上限（字节数/3 的保守换算，含 1.5x 安全系数）× 输入单价 + 输出上界 × 输出单价，向上取整。
- 理由：没有输出上界就无法证明预留覆盖全部费用，严格预算会退化为事后扣账，违反 §23 禁止条款。注入参数属于计划允许的"可验证上界"实现方式。
- 影响：客户端不能请求超过上界的输出；超出部分属于"该调用形式不进入严格预算支持清单"的落地。结算时若 actual > reservation，按 §18.3 记账不截断并告警、置账号 recovery_hold。
- 待验证：上游是否总是尊重 max_output_tokens（P0-02）。在验证前该行为标记 pending，严格模式下无法设定上界的请求形式（如某些工具强制长输出）返回 unsupported。

## D-002 输入 token 估算

- 日期：2026-09-12
- 决策：第一版不做真实 tokenizer，预留用 `ceil(utf8_bytes/3)*1.5` 的保守上界估算输入 token。结算使用上游返回的真实 usage 字段。
- 理由：预留只需可证明上界；真实计量以结算为准。避免引入与上游不一致的 tokenizer 造成错误"精确"。
- 影响：预留偏大，预算消耗体验偏保守；结算后释放差额。

## D-006 review 动作的语义

- 日期：2026-09-12
- 规格：§20 review 为"当前请求暂停并返回审核拒绝类错误，等待人工复核后由用户重新发起"。
- 决策：review 命中返回 HTTP 400 + error.code=audit_blocked（可自动重试=false），审计事件 decision=review，请求终态 audit_failed(=rejected 分支)。复核界面仅记录结论或创建精确例外（§17.2），不自动放行原请求。
- 影响：与计划一致；复核不会重放请求。

## D-007 队列与并发为单实例内存实现

- 日期：2026-09-12
- 规格：§14 单活后端；本地并发计数、队列和缓存不能在第二实例启动时悄悄失效。
- 决策：审核队列、并发槽、缓存均为进程内实现；数据库 advisory lock（`subai_singleton`）作为单活选主锁，第二实例启动时获取锁失败则拒绝启动服务（显式禁止模式）。
- 影响：满足 §14；扩容走升级单实例路线。

## D-008 price_versions 的种子来源

- 日期：2026-09-12
- 规格：§8 首次无有效价格不得调用；§23 禁止伪造同步功能。
- 决策：初始化写入一份标记 origin=synthetic 的种子价格版本（仅覆盖测试与演示所需模型，数值为占位示例，非官方价格），管理界面明确显示"synthetic，未经验证"。真实同步成功并验证后激活 origin=official 的版本。管理员可在 synthetic 激活状态下显式确认"允许合成价格"用于内部测试，但 production_ready 门槛要求存在已验证的 official 版本。
- 影响：满足"首次无有效价格不得调用"与"不伪造同步"的双重约束。

## D-009 审核输入缓存不存原文

- 日期：2026-09-12
- 决策：缓存键 = HMAC-SHA256(规范化内容 || key作用域 || 规则版本 || 审核模型 || 策略版本)，值为统一审核结果结构；TTL 默认 600s；规则/策略/模型任一版本变化自动失效（版本在键内）。
- 影响：与 §6.2、§21 一致。

## D-010 WebSocket 第一版不支持

- 日期：2026-09-12
- 规格：§17.1 WebSocket 需覆盖每一轮消息审核，单独列能力项。
- 决策：第一版数据面仅实现 POST /v1/responses 与 GET /v1/models；WS 返回 422 + error.code=unsupported_transport 并在兼容矩阵标 unsupported。/v1/chat/completions 同样返回 unsupported（Hermes 实际需要时再实现）。
- 影响：明确缩小支持范围，符合 §10 P0 门槛"明确支持与拒绝的调用形式"。
